# 海外仓智能排班 PRD 精简总结

## 一句话目标

为海外仓提供独立的智能排班流程，结合业务环节预测量、人效与人员成本，对 T+3 至 T+10 的临时工工时和正式员工人数生成可调整、可发布的排班结果。

## 本期范围

1. **确定人员范围**：选择部门和业务环节组，支持单选、多选、全选；聚合跨考勤组人员。
2. **调整预测参数**：展示未来 8 天预测单量、人效、推荐工时和人数目标；业务环节工时只读，常规/职能人数可编辑。
3. **确认排班结果**：按人员 × 日期展示班次，支持替换推荐班次；对比推荐与实际工时/人数，并查看明细。
4. **自动排班**：部门级开关；按仓库当地时间每日触发，自动生成 T+3 至 T+10 排班并发送异常提醒。
5. **沿用能力**：复用标准班次库、班次颜色和发布流程；不在当前页面维护班次基础数据。

## 明确不在本期

- 排班监控页：指标口径尚未确定，评审明确暂缓。
- 预测算法、大数据侧生产逻辑：页面仅消费数据，不负责算法实现。
- 修改标准班次库：结果页只允许替换引用的班次。

## 海外版与国内版核心差异

- 国内以考勤组、正式员工、按天排班为主；海外按业务环节聚合人员，临时工占比高，按小时排班。
- 海外需要同时表达“临时工工时”和“正式员工人数”两套目标口径。
- 海外推荐逻辑需考虑技能、质量、成本与业务环节需求，而不是只按固定考勤组排班。

## 优化前后对比

| 原 PRD/评审表达 | 优化后方案 | 收益 |
| --- | --- | --- |
| 国内智能排班入口难以限制总部人员只能使用智能排班 | 海外智能排班作为独立菜单，流程与权限单独配置 | 降低权限和功能混淆 |
| 环节组存在单选、多选、全选多种口径，表达不统一 | 统一为可搜索多选，下拉内支持全选；默认带出可用环节 | 操作路径一致，兼容复杂业务 |
| 预测单量、工时、人数“直接平铺”，编辑边界不明显 | 统一预测矩阵；只读业务工时和可编辑正式员工人数使用不同状态 | 降低误操作，明确算法与人工职责 |
| 推荐结果只展示班次，缺少推荐与实际差异解释 | 顶部增加工时/人数对比，并提供明细下钻 | 帮助排班负责人判断是否接受推荐 |
| 班次替换交互依赖拖拽描述，学习成本和实现风险高 | 原型先采用点击轮换/选择替换，后续可升级为拖拽 | 首期更稳定，移动精度要求更低 |
| 自动排班只描述“每日零点触发”，异常处理不完整 | 配置中补充仓库时区、预测缺失/人员不足提醒 | 增强可运维性和跨时区准确性 |
| 监控页面指标未定但混在当前需求中 | 明确移出本期，保留后续指标确认入口 | 防止范围蔓延，便于按期交付 |
